# MCP Unix signal validation

Three test-only regressions now send real SIGINT/SIGTERM to an isolated child test process. They use the production `ShutdownSignals::install`, `ShutdownSignals::wait`, `finish`, headless listener and runtime shutdown deadline. A third case sends SIGTERM after handler installation but before `wait` is called, covering an already-pending shutdown signal.

Each test first verifies the actual loopback health response. After the signal, it requires the listener port to be reclaimable while the child and its Tokio runtime are still alive, then permits the child to exit successfully. A normal OS process exit therefore cannot stand in for graceful listener cleanup. Temporary directories and owned child processes are cleaned up on failure; signals target only the test's own child PID. The ignored `unix_signal_child` entry is a helper explicitly invoked by the three parent tests, not an unexecuted product case. These Unix-only tests require `/bin/kill` and existing `tempfile`/Tokio dependencies; no dependency is added.

In the offline Linux harness, the three tests pass, including five repeated rounds. Together with the previous four SSE lifecycle tests, all 54 MCP module tests pass, plus the one helper entry intentionally ignored in the outer run. Registering SIGHUP in place of SIGTERM makes the two TERM cases fail. Dropping the cleanup future instead of running it makes all three tests fail because the port is still bound before process exit. Both mutations were restored.

The complete candidate MCP module files are byte-identical to the executed harness inputs. This remains narrow component integration: the tests compose production signal and listener primitives but do not invoke `headless::run`/`run_with_shutdown` as a packaged app, construct the real App, read accounts, initialize diagnostics, exercise Canvas/model calls, or test GUI/Windows/macOS behavior. It is not a full pinned-toolchain build or complete native acceptance result. Only tests, their `cfg(test)` declarations and validation notes changed; production behavior did not change.
